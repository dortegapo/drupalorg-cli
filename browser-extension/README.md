# drupalorg-cli browser companion

This optional WebExtension prefills the Drupal.org contributed project form
from a URL fragment generated by `drupalorg-cli`. It is never required: if the
companion is not installed or published for the selected browser, the CLI
opens the normal Drupal.org form and the user completes it manually.

The companion is deliberately limited to:

- `https://www.drupal.org/node/add/project-module*`;
- reading the `drupalorg-cli-prefill` URL fragment;
- filling the supported form fields in the current page.

It does not read, export, save, or reuse cookies. It does not inspect or
modify Drupal.org authentication state, CSRF tokens, `form_build_id`,
`form_token`, or `form_id`. It never submits the form and never presses Save
or Preview. Submission is intentionally left to the user; review every field
before pressing Save.

## End-user installation

End users should select their browser in `drupalorg-cli project:publish` or
run `drupalorg browser:setup`. The CLI will open the corresponding official
store listing when one is available. Store listing URLs are intentionally not
embedded here until the companion is published. If no listing is available,
the CLI keeps the manual Drupal.org workflow.

The browser companion stores no Drupal.org credentials or form data. The CLI
stores only the selected browser family in its local configuration so it does
not ask for the browser on every run.

## Development installation

The current repository distribution is for development and testing only. It
uses the shared `prefill.js` source and the Chromium-compatible `manifest.json`.

In Chromium, Chrome, or Edge:

1. Open the browser's extensions page.
2. Enable developer mode.
3. Choose **Load unpacked**.
4. Select this `browser-extension/` directory.
5. Open `https://www.drupal.org/node/add/project-module` through
   `drupalorg-cli` and review the prefilled form.

For a Firefox development package, copy `manifest.firefox.json` to a package
directory as `manifest.json` alongside `prefill.js`, then load that package
using Firefox's development tooling. This is a development workflow only and
is not used as an end-user installation shortcut.

Safari packaging and store publication are not available yet. The shared
source and form contract can be reused when a Safari companion is published.

The payload is carried in the URL fragment, which is removed from the address
bar and browser history as soon as the companion reads it. The fragment is not
sent in the HTTP request to Drupal.org.

The extension uses no Node.js, npm, bundler, or external runtime.
